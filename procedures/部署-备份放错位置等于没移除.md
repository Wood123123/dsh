# 部署-备份放错位置等于没移除

> **触发**：把插件/mod 从 `BepInEx\plugins` 里"移除"了，但游戏里它还在跑；或者别的客户端莫名多出插件
> **验证**：启动后看 `BepInEx\LogOutput.log` 里 `[Info : BepInEx] Loading [<插件名>` 是否还出现

## 首选

把备份移到 **`BepInEx` 目录树之外**：

```
F:\EFT\_plugin_backups\<名字>_<时间戳>\
\\<服务端机>\c\...\EFT-headless\_plugin_backups\...
```

## 被挡时

1. 若必须留在场内，改扩展名：`X.dll` → `X.dll.disabled`（BepInEx 只加载 `.dll`）
   ⚠ 但 **NarcoNet 仍会分发它**（只是无害）
2. 临时应急：在 NarcoNet 的排除列表里加那个路径

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| 移到 `BepInEx\plugins\_removed\` | **BepInEx 递归扫描 plugins 的所有子目录** ⇒ 照样加载 |
| 移到 `plugins\_backup\` | 同上，而且还被 NarcoNet 当作正式文件推给所有客户端 |

## 注意

- **两个机制叠加导致这个坑很隐蔽**：
  1. BepInEx **递归加载** `plugins\` 下任意深度的 `.dll`
  2. NarcoNet 的 `served-paths.json` 含整个 `BepInEx/plugins` ⇒ **整个目录（含备份）都会推给所有客户端**
- 判据：**备份位置既不能在 BepInEx 树内，也不能在 NarcoNet 的 served-paths 内**
- 安全的两个位置（本环境）：
  - 游戏端：`F:\EFT\_plugin_backups\`
  - 服务端：`...\SPT_Runtime\_plugin_backups\`（**不能**放 `SPT_Runtime\user\mods\` —— 那也在 served-paths 里）

证据：2026-10-16 会话；`BepInEx\LogOutput.log` 实测仍加载 TransitDiag/TransitOverlay/ShijiuReconnectFix
