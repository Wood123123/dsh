# 诊断-静态扫描必须核守卫

> **触发**：用 Cecil/ILSpy 扫"每帧方法里的危险调用"（FindObjectsOfType / LINQ / 日志），得出"这个 mod 有 10 次全场景扫描，风险分 820"
> **验证**：把那个方法的前 10~15 条指令打出来 —— 必定有早退守卫

## 首选

**扫出危险调用后，必须再读方法开头的守卫，否则结论一定虚高。**

```powershell
# 反向验证：危险调用在第几条？守卫跳转跳过它了吗？
$m.Body.Instructions | Select-Object -First 15 |
  ForEach-Object { '{0,-14} {1}' -f $_.OpCode.Name, $_.Operand }
```

**识别守卫的三种形态：**

| 形态 | IL 特征 | 例子 |
|---|---|---|
| **配置开关** | `ldsfld ConfigEntry<bool>` → `callvirt get_Value` → `brfalse IL_xxxx` | `ManimalIcebreaker.Plugin::DevMode`（默认 false ⇒ 整段跳过） |
| **状态标志** | `ldsfld static bool` → `brtrue/brfalse` | `FikaPause::_installed`、`DragPreview::_failed` |
| **对象存在性** | `ldsfld obj` → `op_Equality(ldnull)` → `brtrue ret` | `CompactTooltip::_root`、`TrajectoryRenderer::_line` |

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| 按"危险调用数量"给插件打风险分排序 | 绝大多数调用在不满足条件时**根本不执行** |
| 只看方法长度（指令数）判断开销 | 2282 指令的 `RenderEnvProbe.Update` 在 `DevMode=false` 时只跑 4 条指令 |
| 用静态扫描的结果直接下优化结论 | 会得出"10 次 FindObjectsOfType 很危险"，实际一次都不跑 |

## 注意

- **实测案例**：`Manimal.Icebreaker.RenderEnvProbe.Update` [2282 指令]
  含 `FindObjectsOfType<MeshRenderer>()` 等 4 次全场景扫描 + `Camera.main` + 9 处日志
  **但前 6 条指令是**：
  ```
  0 call    FikaBridge::get_CanRender() ; 1 brtrue ; 2 ret
  3 ldsfld  Plugin::DevMode             ; 4 get_Value ; 5 brfalse IL_032a  ← 跳过全部危险调用
  ```
  而配置里 `DevMode = false` ⇒ **实际开销 ≈ 0**
- **静态扫描能回答的**：有哪些风险点**存在**
- **静态扫描不能回答的**：这些风险点**会不会执行**
- **判据**：如果一篇性能分析只给了"指令数 / 调用数"而没给"守卫条件"，它一定高估
- **补一步**：所有"每帧方法"都要读前 15 条指令确认守卫；没有守卫的才是真开销

证据：2026-10-16 会话；Cecil 扫 103 个客户端 dll，风险分 820 的插件实际开销≈0
