# 环境-换机器时全局钩子不跟着走

> **触发**：新机器上 agent 不读 `_索引.md`、不查 `procedures/`，像第一次见这个项目
> **验证**：新会话里问一句「这个工作区有什么」，看它是否直接引用 `_索引.md` 的内容

## 首选

换机器时**三样都要搬**，缺一不可：

```powershell
# ① 用户全局钩子（★ 最容易漏 —— 它在工作区之外，不跟 git 走）
Copy-Item "$env:USERPROFILE\.dsh\AGENTS.md" "<新机器>\C:\Users\<用户>\.dsh\AGENTS.md"

# ② 工作区（.gitignore 已排除 99%，只剩 8 MB）
git clone <远程> <工作区>

# ③ 机器本地路径（在新机器上重新探测生成）
cd <工作区>
powershell -NoProfile -ExecutionPolicy Bypass -File bootstrap.ps1 -GameRoot "D:\EFT" -ServerHost "<服务端>"
```

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| 只搬工作区，不搬 `~/.dsh/AGENTS.md` | 项目钩子只保证「读索引」，**procedures 的读卡约定丢了** |
| 指望子目录 `AGENTS.md` 单独生效 | 项目链从 **`.git` 标记的项目根**往下走；没有 `.git` 就断链 |
| 把 工作区 设成 `dsh\工作区\<项目>` 去开会话 | 没有 `.git` 时项目链上不到 dsh，读不到 dsh 的 AGENTS.md |
| 同步 826 MB 的缓存区进 git | `.gitignore` 已排除；硬塞进去会让 clone 变成几分钟 |

## 注意

- **DSH 的指令加载规则**（实测）：
  - 两级：`$DSH_HOME\AGENTS.md`（用户全局）→ 项目链（项目根到会话工作目录，从宽到窄）
  - 项目根由 `.git` 标记
  - **动态发现**：read/write/edit 到达更深目录后，下一次请求自动带上那个目录的 AGENTS.md
    ⇒ 子目录 AGENTS.md 是**自动生效**的，不用手动指路
- 判据：新会话里 agent 的**第一条动作**是读 `_索引.md`，而不是 `ls` 或全盘 grep

证据：2026-10-16 会话；`@deepseek-ai/dsh-agent-instructions` 的 README 描述 + 实测 system-reminder
