# 诊断-区分403是谁返回的

> **触发**：请求返回 403，但不确定是「目标站拒绝」还是「本机代理/加速器拦的」
> **验证**：看 `Server` 响应头和响应体措辞

## 首选

```powershell
$req = [System.Net.HttpWebRequest]::Create($url)
$req.UserAgent = 'app/1.0'
try { $r = $req.GetResponse() }
catch [System.Net.WebException] {
    $r = $_.Exception.Response
    "HTTP {0}" -f [int]$r.StatusCode
    "Server: {0}" -f $r.Headers['Server']
    # ★ 这两类头决定根因
    "x-accepted-*: {0}" -f $r.Headers['x-accepted-github-permissions']
    $sr = New-Object System.IO.StreamReader($r.GetResponseStream()); $sr.ReadToEnd()
}
```

**判据表：**

| 看到的 | 是谁 | 怎么办 |
|---|---|---|
| `Server: github.com,...` + 有 `x-accepted-*-permissions` | **目标站**说"你缺权限" | 补 token 权限 |
| `Server: <加速器名>` + 响应体 `forbidden by administrative rules` | **本地加速器**在拦 | 补 User-Agent；或改用走系统代理的客户端 |
| 响应体里有目标站的 JSON 错误结构 | 目标站 | 按它说的改 |
| HTTP 000（不是 403） | 连接就没建立 | 见「环境-curl和HttpWebRequest不走本地加速器」 |

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| 403 就当权限问题去改 token | 有一半情况是本地代理拦的，改 token 没用 |
| 403 就当网络问题去换代理 | 另一半情况确实是权限 |
| 只看状态码不看响应头 | `Server` 头 + `x-accepted-*` 头一秒钟就能定性 |

## 注意

- **本机 `Server` 头会被加速器改写**（实测见过 `Server: github.com,WattToolkit`）。
  格式是 `<真实站>,<加速器名>` —— 逗号后面是本地那一层
- **`x-accepted-*-permissions` 是"你要做这个动作需要什么权限"**，
  不是"你有什么权限"。它出现在 403 上时，列出的是**缺的那些**
- 拿不到响应头（连 `Response` 都是 null）⇒ 是连接层失败，不是 HTTP 层

证据：2026-10-16 会话；同一天遇到两种 403：GitHub 的 `administration=write` 与加速器的
`Request forbidden by administrative rules`
